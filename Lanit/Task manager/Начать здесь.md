# Задачи: SQLite + SQLAlchemy + Obsidian

[[Доска задач.canvas|Открыть карточки и связи]] · [[Сроки.base|Таблица сроков]]

## Как устроено
- **Данные/tasks.sqlite3** — основная база данных: задачи, тексты, даты и зависимости.
- **Управление/models.py** — модели SQLAlchemy 2.0, таблицы `tasks` и `dependencies`.
- **Управление/tasks.py** — создание, изменение, статусы, зависимости, импорт и резервная копия.
- **Управление/export_obsidian.py** — формирование Markdown и холста.
- **Управление/Управление задачами.ipynb** — интерфейс для работы в VS Code.
- **Задачи/** — экспортированные заметки в папках To Do, В работе и Выполнено.

Obsidian отображает данные. Изменения в экспортированных заметках не записываются в SQLite и будут заменены при экспорте. Для редактирования текста используйте `manager.update(id, текст=...)`. Папки статусов и холст формируются автоматически. Ручные перемещения карточек при обновлении заменяются.

## Запуск в VS Code
1. Распакуйте этот комплект в отдельную новую папку. Его можно разместить внутри существующего хранилища Obsidian, например рядом с прежним Task manager. Не заменяйте старую папку целиком.
2. Откройте новую папку в VS Code и ноутбук из «Управление».
3. Нужны расширения Microsoft Python и Jupyter. Выберите своё ядро Python 3.10+.
4. Выполните установочную ячейку, затем ячейку подключения. JupyterLab не требуется.
5. Команды, меняющие данные, в примерах закомментированы. Уберите комментарий только у нужной команды.

В новом комплекте база с тремя демонстрационными задачами и связью. Для своего чистого менеджера распакуйте отдельную копию; до первого запуска удалите **Данные/tasks.sqlite3**, примеры из **Задачи/** и **Доска задач.canvas**. При подключении пустая база создастся автоматически. Это допустимо только для нетронутой демонстрационной копии.

## Импорт существующих задач
Сначала сохраните копию старой папки менеджера. В ноутбуке укажите путь к старой папке **Задачи** и запустите `manager.import_notes(...)`. Например:
```python
manager.import_notes(r"C:\Users\Donchenko\Documents\obsidian_db\Lanit\Task manager\Задачи")
```
Используйте фактический путь своего компьютера. Импорт читает три папки прежнего формата, сохраняет тело заметок и свойства, не меняет исходные файлы. Повторный импорт из тех же путей пропускает уже импортированные задачи. Это одноразовый перенос, не двусторонняя синхронизация. Связи старого Canvas не импортируются: зависимости задаются явно в ноутбуке.

Если дата появления в старой заметке отсутствует, она остаётся неизвестной и на карточке показывается «не указана». Исправьте через `manager.update(id, создано="2026-09-15")`. Для новой задачи дата появления по умолчанию — сегодня; параметр `created` позволяет указать настоящую дату задним числом. Дата изменения файла не выдаётся за дату появления задачи.

## Карточки и зависимости
Одна задача — одна карточка исходной заметки. На ней явно видны дата появления, срок, статус, приоритет и содержание. Синий — план, жёлтый — работа, зелёный — выполнено. Просрочка отмечена текстом. Карточки расположены уровнями: сначала предшественники, ниже зависимые задачи.

**А → Б означает «Б зависит от выполнения А».** Команда: `manager.depend(Б, А)`. Если есть несколько предшественников, завершить нужно всех. Циклы запрещены. Начать или завершить заблокированную задачу нельзя. Чтобы вернуть завершённого предшественника в работу, сначала верните зависимые активные задачи в To Do, начиная с конца цепочки.

## Повседневная работа
Изменения через менеджер сохраняются в базу, затем экспортируются. Перед экспортом закройте вкладку холста в Obsidian, после откройте снова. Не редактируйте SQLite из двух ноутбуков одновременно. Не держите разные копии модуля `tasks.py` в одном ядре: после перехода со старого комплекта перезапустите ядро.

`manager.export()` повторно формирует заметки и холст и обновляет подсветку просрочки. Если экспорт завершился ошибкой после изменения, данные уже находятся в базе: устраните причину и повторите экспорт. Таблица Bases доступна при включённом встроенном плагине Bases; редактировать её поля не следует, поскольку это изменит лишь экспортированные заметки.

`manager.backup()` создаёт согласованную резервную копию SQLite. Для восстановления закройте ядро и замените файл базы нужной копией, затем снова подключитесь и экспортируйте. Храните базу и резервные копии; Markdown является представлением данных.
